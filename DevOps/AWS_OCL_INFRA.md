## 1. 문서 목적

이 문서는 회사 시스템이 **어디에서**, **어떤 구조로**, **무엇 위에서** 돌아가는지 이해하기 위한 가장 기초적인 안내서입니다.

이 문서를 읽고 나면 아래 질문에 답할 수 있는 상태를 목표로 합니다.

- 클라우드가 무엇인가?
- Oracle Cloud와 AWS는 무엇이 다른가?
- 서버, 디스크, 네트워크는 각각 어떤 역할을 하는가?
- 우리 서비스는 어디에 배포되는가?
- 서비스가 안 될 때 프로그램 문제인지, 인프라 문제인지 어떻게 구분할 수 있는가?

## 2. 인프라란 무엇인가

인프라는 쉽게 말하면 **서비스가 돌아가기 위한 바닥 시설**입니다.

예를 들어 회사에서 사용하는 웹사이트나 업무 시스템은 단순히 프로그램 코드만 있다고 동작하지 않습니다.  
그 프로그램이 실행될 **컴퓨터**, 데이터를 저장할 **저장공간**, 서로 연결될 **네트워크**, 외부에서 접속할 **주소**, 접근을 통제할 **보안 규칙**이 필요합니다.

즉, 인프라는 다음을 포함하는 큰 개념입니다.

- 서버
- 저장공간
- 네트워크
- 외부 접속 주소
- 보안 설정
- 데이터베이스
- 클라우드 환경

한마디로 정리하면:

> **인프라 = 프로그램이 일할 수 있도록 준비된 집과 도로와 창고와 출입문**

---

## 3. 클라우드란 무엇인가

클라우드는 **인터넷으로 빌려 쓰는 서버와 인프라 환경**입니다.

예전에는 회사가 직접 컴퓨터 서버를 구매해서 사무실이나 서버실에 두고 운영하는 경우가 많았습니다.  
하지만 지금은 Oracle Cloud, AWS 같은 회사에서 서버와 네트워크를 빌려 쓰는 방식이 일반적입니다.

쉽게 비유하면:

- **내가 직접 컴퓨터를 사서 회사에 두는 것** = 직접 서버 운영
- **필요한 만큼 인터넷으로 컴퓨터를 빌려 쓰는 것** = 클라우드

즉:

> **클라우드는 인터넷 위에 빌린 컴퓨터와 그 주변 시설**

이라고 이해하면 됩니다.

---

## 4. Oracle Cloud(OCI)와 AWS란 무엇인가

Oracle Cloud Infrastructure(OCI)와 AWS는 둘 다 **클라우드 서비스를 제공하는 플랫폼**입니다.

둘 다 기본적으로 아래 같은 것을 제공합니다.

- 서버
- 저장공간
- 네트워크
- 보안 규칙
- 데이터베이스
- 기타 운영 기능

즉, 이름은 다르지만 둘 다 본질은 비슷합니다.

- **OCI** = Oracle의 클라우드
- **AWS** = Amazon의 클라우드

## 5. 건물 비유로 이해하는 인프라

인프라는 처음 보면 용어가 어렵습니다.  
그래서 아래처럼 **건물 비유**로 이해하면 훨씬 쉽습니다.

| 인프라 개념 | 쉬운 비유 |
|---|---|
| 서버 | 사무실 안의 컴퓨터 |
| 디스크 | 서랍장 / 저장창고 |
| 네트워크 | 도로 / 복도 |
| 가상 네트워크 | 내가 빌린 건물 단지 |
| 서브넷 | 단지 안의 구역 |
| 공인 IP | 건물 주소 |
| 보안 규칙 | 경비실 출입 규칙 |

이 문서에서는 이 비유를 계속 사용합니다.

## 6. 서버란 무엇인가

서버는 쉽게 말하면 **프로그램이 실행되는 컴퓨터**입니다.

우리가 집에서 노트북으로 프로그램을 실행하듯이,  
회사 서비스도 어딘가의 컴퓨터에서 실행되어야 합니다. 그 컴퓨터를 서버라고 부릅니다.

클라우드에서는 이 서버를 가상으로 빌립니다.

- OCI에서는 보통 **Compute Instance**
- AWS에서는 보통 **EC2 Instance**

라고 부릅니다.

즉:

> **서버 = 프로그램이 일하는 컴퓨터**

---

## 7. 디스크란 무엇인가

디스크는 **저장공간**입니다.

서버가 컴퓨터라면, 디스크는 그 컴퓨터 안에서 파일과 데이터를 저장하는 공간입니다.

예를 들어 아래 같은 것들이 디스크에 저장될 수 있습니다.

- 프로그램 파일
- 설정 파일
- 로그 파일
- 업로드 파일
- 데이터베이스 파일

비유하면:

- 서버 = 컴퓨터 본체
- 디스크 = 하드디스크 / 서랍장 / 창고

즉:

> **디스크 = 데이터를 보관하는 공간**

---

## 8. 네트워크란 무엇인가

네트워크는 **컴퓨터끼리 연결되는 길**입니다.

서버가 혼자만 있으면 아무 일도 할 수 없습니다.  
사용자도 접속해야 하고, 데이터베이스와도 통신해야 하고, 다른 서버와도 연결되어야 합니다.

이 연결 관계를 가능하게 해주는 것이 네트워크입니다.

비유하면:

- 서버 = 사무실
- 네트워크 = 사무실까지 이어지는 도로와 복도

즉:

> **네트워크 = 컴퓨터들이 서로 오갈 수 있는 길**

---

## 9. 가상 네트워크란 무엇인가

가상 네트워크는 클라우드 안에서 내가 만든 **나만의 네트워크 공간**입니다.

쉽게 말하면:

- OCI에서는 **VCN**
- AWS에서는 **VPC**

라고 부릅니다.

비유하면:

> **가상 네트워크 = 내가 빌린 건물 단지 전체**

그 안에 서버도 두고, 데이터베이스도 두고, 출입 규칙도 정합니다.

즉:

> **가상 네트워크는 클라우드 안에서 내 서버들이 모여 있는 울타리**

---

## 10. 서브넷이란 무엇인가

서브넷은 **가상 네트워크 안의 더 작은 구역**입니다.

비유하면:

- 가상 네트워크(VCN/VPC) = 아파트 단지 전체
- 서브넷 = 단지 안의 101동, 102동 같은 구역

보통 서브넷은 아래처럼 나눌 수 있습니다.

### 공용 서브넷
외부 인터넷과 직접 연결될 수 있는 구역

### 사설 서브넷
외부에서 바로 들어오지 못하는 내부 구역

비유하면:

- 공용 서브넷 = 1층 로비
- 사설 서브넷 = 직원만 들어가는 내부 사무실

즉:

> **서브넷 = 네트워크 안의 작은 구역**

---

## 11. 공인 IP란 무엇인가

공인 IP는 인터넷에서 보이는 **외부 주소**입니다.

서버가 있어도 주소가 없으면 외부 사용자는 그 서버를 찾을 수 없습니다.  
공인 IP는 외부에서 내 서버를 찾기 위한 주소 역할을 합니다.

비유하면:

> **공인 IP = 건물의 도로명 주소**

공인 IP가 없으면 외부 접속이 어렵고, 공인 IP가 있어도 보안 규칙이 막혀 있으면 여전히 접속이 안 될 수 있습니다.

---

## 12. 보안 규칙이란 무엇인가

보안 규칙은 **누가 어떤 길로 들어올 수 있는지 정하는 출입 규칙**입니다.

서버가 있다고 해서 모든 사람이 아무 문으로나 들어오게 할 수는 없습니다.  
그래서 클라우드에서는 어떤 접속을 허용할지 규칙을 정합니다.

비유하면:

> **보안 규칙 = 경비실 출입 규칙**

예를 들면:

- 관리자만 들어올 수 있는 문
- 웹사이트 접속용 문
- 특정 시스템만 접근 가능한 문

즉:

> **보안 규칙 = 어떤 문을 열어둘지 정하는 것**

---

## 13. 포트란 무엇인가

포트는 **서버 안의 출입문 번호**라고 생각하면 쉽습니다.

서버 주소만 있다고 바로 모든 서비스에 연결되는 것은 아닙니다.  
같은 서버 안에서도 서비스마다 사용하는 문이 다를 수 있습니다.

예를 들어:

- `22`: 서버 원격 접속
- `80`: 일반 웹 접속
- `443`: 보안 웹 접속

비유하면:

- 공인 IP = 건물 주소
- 포트 = 그 건물의 몇 번 출입문인지

즉:

> **포트 = 서버 안의 서비스별 문 번호**

---

## 14. 배포란 무엇인가

배포는 쉽게 말하면:

> **내 프로그램을 서버에 올려서 실제로 사용할 수 있게 만드는 것**

입니다.

예를 들어 회사 프로그램을 배포한다는 것은 보통 아래 과정을 의미합니다.

1. 클라우드에 서버를 준비한다
2. 프로그램 파일을 서버에 올린다
3. 실행한다
4. 외부에서 접속 가능한 주소와 규칙을 맞춘다
5. 실제 사용자가 접속하게 만든다

즉:

> **배포 = 프로그램을 실제 서비스 가능한 상태로 올리는 과정**

## 15. Oracle Cloud(OCI) 기본 개념

Oracle Cloud에서 가장 먼저 알아야 할 기본 요소는 다음과 같습니다.

### 1) Compute Instance
클라우드 서버 한 대  
= 프로그램을 실행하는 컴퓨터

### 2) VCN
서버들이 들어가는 가상 네트워크  
= 서버들이 놓이는 단지

### 3) Subnet
VCN 안의 작은 구역  
= 단지 안의 구획

### 4) Security Rules / NSG / Security List
출입 규칙  
= 경비실 규칙

쉽게 말하면 OCI에서는 보통 아래 순서로 생각합니다.

1. 네트워크(VCN)를 만든다
2. 그 안의 구역(Subnet)을 나눈다
3. 서버(Compute)를 만든다
4. 주소와 보안 규칙을 설정한다
5. 프로그램을 올린다

---

## 16. AWS 기본 개념

AWS에서 가장 먼저 알아야 할 기본 요소는 다음과 같습니다.

### 1) EC2
클라우드 서버 한 대  
= OCI의 Compute와 비슷한 개념

### 2) VPC
가상 네트워크  
= OCI의 VCN과 비슷한 개념

### 3) Subnet
VPC 안의 작은 구역

### 4) Security Group
출입 규칙  
= OCI 보안 규칙과 비슷한 개념

쉽게 말하면 AWS에서도 보통 아래 순서로 생각합니다.

1. 네트워크(VPC)를 준비한다
2. 구역(Subnet)을 나눈다
3. 서버(EC2)를 만든다
4. 보안 규칙(Security Group)을 설정한다
5. 프로그램을 올린다

## 17. OCI와 AWS 쉬운 대응표

| 하고 싶은 일 | OCI 이름 | AWS 이름 |
|---|---|---|
| 서버 한 대 만들기 | Compute Instance | EC2 |
| 가상 네트워크 만들기 | VCN | VPC |
| 네트워크 안의 구역 나누기 | Subnet | Subnet |
| 출입 규칙 정하기 | Security List / NSG | Security Group |

즉 외우는 방법은 아주 단순합니다.

- **OCI 서버 = Compute**
- **AWS 서버 = EC2**
- **OCI 네트워크 = VCN**
- **AWS 네트워크 = VPC**

## 18. 회사 서비스는 보통 어떤 구조로 운영되는가

아주 단순하게 보면 회사 서비스는 보통 아래 흐름으로 운영됩니다.

```text
사용자
  ↓
인터넷
  ↓
클라우드 주소(공인 IP 또는 도메인)
  ↓
클라우드 서버
  ↓
프로그램
  ↓
데이터 저장소
```

이걸 건물 비유로 바꾸면 이렇습니다.

* 사용자 = 방문객
* 인터넷 = 외부 도로
* 공인 IP = 건물 주소
* 서버 = 사무실 컴퓨터
* 디스크/DB = 서류 보관실

즉 서비스는 “프로그램만” 있는 것이 아니라,
그 프로그램이 놓일 자리가 필요합니다.

## 19. 장애가 났을 때 생각하는 순서

서비스가 안 될 때는 무조건 프로그램만 의심하면 안 됩니다.

아래 순서로 생각하면 훨씬 쉽습니다.

### 1) 서버가 살아 있는가?

컴퓨터 자체가 켜져 있는가

### 2) 외부 주소가 연결되는가?

공인 IP나 도메인이 맞는가

### 3) 보안 규칙이 막고 있지 않은가?

문은 열려 있는가

### 4) 프로그램이 정상 실행 중인가?

애플리케이션이 떠 있는가

### 5) 저장소/DB 연결은 정상인가?

데이터를 읽고 쓸 수 있는가

즉 장애는 크게 아래 네 종류로 나눠 생각할 수 있습니다.

* 서버 문제
* 네트워크 문제
* 보안 규칙 문제
* 프로그램 문제

## 20. 꼭 알아야 할 최소 핵심 정리

이 문서에서 가장 중요한 핵심만 다시 정리하면 아래와 같습니다.

### 1) 인프라

프로그램이 돌아가기 위한 기반 시설

### 2) 클라우드

인터넷으로 빌려 쓰는 서버와 인프라

### 3) 서버

프로그램이 실행되는 컴퓨터

### 4) 디스크

데이터를 저장하는 공간

### 5) 네트워크

컴퓨터끼리 연결되는 길

### 6) 가상 네트워크

클라우드 안의 나만의 네트워크 공간

* OCI: VCN
* AWS: VPC

### 7) 서브넷

가상 네트워크 안의 작은 구역

### 8) 공인 IP

외부에서 찾아오는 주소

### 9) 보안 규칙

어떤 문을 열어줄지 정하는 출입 규칙

### 10) 배포

프로그램을 서버에 올려 실제로 사용할 수 있게 만드는 것

## 21. 결론

* 회사 프로그램은 그냥 실행되는 것이 아니라 **서버 위에서** 돌아간다.
* 그 서버는 **클라우드 환경** 안에 있을 수 있다.
* 서버는 **네트워크와 저장공간과 보안 규칙** 안에서 움직인다.
* 서비스 장애는 프로그램 문제만이 아니라 **인프라 문제**일 수도 있다.
* OCI와 AWS는 이름은 달라도 비슷한 구조를 가진다.
