## 2. 먼저 큰 그림부터 보기

회사 서비스는 보통 아래처럼 돌아갑니다.

```text
사용자
  ↓
인터넷
  ↓
서버 주소(IP 또는 도메인)
  ↓
서버
  ↓
프로그램
```

여기서 알아야 할 핵심은 아래와 같습니다.

* **서버**: 프로그램이 실행되는 컴퓨터
* **IP**: 그 컴퓨터의 주소
* **네트워크**: 컴퓨터끼리 연결되는 길
* **Docker**: 프로그램을 실행하기 좋은 상태로 포장해서 쉽게 실행하게 해주는 도구

---

## 3. Docker란 무엇인가

Docker는 한 문장으로 말하면:

> **프로그램과 실행 환경을 함께 포장해서, 어디서든 비슷하게 실행할 수 있게 해주는 도구**

입니다.

프로그램은 단순히 코드만 있다고 바로 실행되지 않습니다.
보통 아래 같은 것들이 함께 필요합니다.

* 자바 / 파이썬 / 노드 같은 실행 도구
* 특정 버전의 라이브러리
* 운영체제 환경
* 설정 파일

문제는 사람마다 환경이 다르다는 것입니다.

예를 들면:

* 내 컴퓨터에서는 잘 됨
* 다른 개발자 컴퓨터에서는 안 됨
* 서버에서는 또 안 됨

Docker는 이 문제를 줄이기 위해 사용합니다.

---

## 4. Docker를 왜 사용하는가

Docker를 사용하는 이유는 다음과 같습니다.

### 1) 실행 환경을 통일하기 위해

같은 프로그램을 여러 컴퓨터에서 비슷하게 실행하기 위해 사용합니다.

### 2) 설치를 단순하게 하기 위해

프로그램마다 필요한 환경을 따로따로 맞추지 않아도 되게 만들 수 있습니다.

### 3) 배포를 쉽게 하기 위해

서버에 프로그램을 옮길 때, 프로그램만이 아니라 실행 환경까지 함께 옮길 수 있습니다.

### 4) 프로그램끼리 덜 충돌하게 하기 위해

서로 다른 프로그램이 다른 설정과 버전을 필요로 해도, Docker로 분리해서 운영할 수 있습니다.

---

## 5. Docker가 해결하는 문제

Docker가 해결하려는 대표적인 문제는 아래와 같습니다.

### 환경 차이 문제

“내 컴퓨터에서는 됐는데 서버에서는 안 돼요” 같은 문제를 줄일 수 있습니다.

### 설치 복잡함

자바 버전, 라이브러리, 설정 등을 일일이 맞추는 부담을 줄일 수 있습니다.

### 배포 불편함

실행 환경까지 포함해서 프로그램을 전달할 수 있으므로 배포가 쉬워집니다.

### 운영 충돌

한 서버 안에서 여러 프로그램이 서로 다른 환경을 써야 할 때 분리 운영하기 좋습니다.

## 6. Docker의 핵심 개념

Docker를 처음 볼 때 가장 많이 나오는 용어는 아래 4개입니다.

---

### 6.1 이미지(Image)

이미지는 쉽게 말하면:

> **실행을 위한 원본 포장본**

입니다.

비유하면:

* 붕어빵 틀
* 밀키트 상품
* 복사 가능한 실행 원본

즉, 이미지는 아직 “실행 중”인 것은 아니고,
**실행할 수 있도록 준비된 원본**입니다.

---

### 6.2 컨테이너(Container)

컨테이너는 쉽게 말하면:

> **이미지를 실제로 실행한 상태**

입니다.

비유하면:

* 밀키트를 뜯어서 조리 중인 상태
* 붕어빵 틀로 실제 구워낸 붕어빵
* 지금 실제로 돌아가는 상자

즉:

* 이미지 = 원본
* 컨테이너 = 실행 중인 결과물

---

### 6.3 Dockerfile

Dockerfile은:

> **이 프로그램을 어떤 환경으로 포장할지 적는 설명서**

입니다.

예를 들면 아래 내용을 적을 수 있습니다.

* 어떤 운영 환경을 쓸지
* 어떤 파일을 넣을지
* 어떤 명령으로 실행할지
* 어떤 포트를 사용할지

즉:

> **Dockerfile = 포장 방법 설명서**

---

### 6.4 Docker Compose

Docker Compose는:

> **여러 개의 컨테이너를 한 번에 관리하는 도구**

입니다.

예를 들어 서비스 하나를 운영하는데 아래 3개가 필요할 수 있습니다.

* 프로그램 컨테이너
* 데이터베이스 컨테이너
* 기타 도구 컨테이너

이것들을 하나씩 따로 띄우는 대신,
Compose 파일로 한 번에 관리할 수 있습니다.

즉:

> **Docker = 개별 상자 관리**
>
> **Docker Compose = 여러 상자를 묶음으로 관리**

---

## 7. Docker를 비유로 이해하기

Docker를 가장 쉽게 이해하려면 **밀키트 비유**가 좋습니다.

### Docker가 없을 때

레시피만 들고 다른 집 주방에 가는 느낌입니다.

문제는:

* 냄비가 다를 수 있고
* 불 세기가 다를 수 있고
* 재료가 없을 수 있고
* 양념이 다를 수 있습니다

그래서 같은 요리라도 결과가 달라질 수 있습니다.

### Docker가 있을 때

밀키트를 들고 가는 느낌입니다.

* 재료가 들어 있고
* 양념이 들어 있고
* 필요한 구성이 정리되어 있고
* 거의 같은 방식으로 만들 수 있습니다

즉:

* 프로그램 = 요리
* Docker = 밀키트 포장

---

## 8. Docker를 실제로 어떻게 사용하는가

실제로 Docker를 사용할 때는 보통 아래 순서로 갑니다.

1. 프로그램이 있다
2. `Dockerfile`을 만든다
3. Docker 이미지(Image)를 만든다
4. 그 이미지를 실행해서 컨테이너를 띄운다
5. 여러 개가 필요하면 `compose.yaml`로 함께 실행한다

즉 흐름은 아래와 같습니다.

```text
Dockerfile → Image → Container
```

---

## 9. Docker 기본 사용 흐름

가장 기본적인 사용 흐름은 아래와 같습니다.

### 1) Dockerfile 작성

프로그램을 어떤 환경으로 실행할지 설명서를 만듭니다.

예:

```dockerfile
FROM eclipse-temurin:17-jre
WORKDIR /app
COPY app.jar app.jar
EXPOSE 8080
CMD ["java", "-jar", "app.jar"]
```

위 의미는 대략 아래와 같습니다.

* 자바 17 환경 사용
* `/app` 폴더에서 작업
* `app.jar` 파일 복사
* 8080 포트 사용
* `java -jar app.jar`로 실행

---

### 2) 이미지 만들기

```bash
docker build -t my-app .
```

뜻:

* `docker build` = 이미지 만들기
* `-t my-app` = 이미지 이름 지정
* `.` = 현재 폴더 기준

즉:

> “현재 폴더에 있는 Dockerfile을 바탕으로 `my-app`이라는 이미지를 만들겠다”

---

### 3) 컨테이너 실행하기

```bash
docker run -d -p 8080:8080 --name my-app my-app
```

뜻:

* `docker run` = 컨테이너 실행
* `-d` = 백그라운드 실행
* `-p 8080:8080` = 내 컴퓨터의 8080과 컨테이너의 8080 연결
* `--name my-app` = 컨테이너 이름 지정
* 마지막 `my-app` = 실행할 이미지 이름

즉:

> “`my-app` 이미지를 바탕으로 `my-app`이라는 이름의 컨테이너를 실행하겠다”

## 10. Docker 자주 쓰는 명령어

### 실행 중인 컨테이너 보기

```bash
docker ps
```

### 모든 컨테이너 보기

```bash
docker ps -a
```

### 이미지 목록 보기

```bash
docker images
```

### 컨테이너 로그 보기

```bash
docker logs 컨테이너이름
```

예:

```bash
docker logs my-app
```

### 실시간 로그 보기

```bash
docker logs -f 컨테이너이름
```

### 컨테이너 중지

```bash
docker stop 컨테이너이름
```

### 컨테이너 삭제

```bash
docker rm 컨테이너이름
```

### 이미지 삭제

```bash
docker rmi 이미지이름
```

## 12. Docker 사용 시 자주 헷갈리는 부분

### 1) 이미지와 컨테이너를 헷갈림

* 이미지 = 원본
* 컨테이너 = 실행 중인 것

### 2) 코드만 바꿨는데 바로 반영될 거라 생각함

보통은 **이미지를 다시 빌드하고** 컨테이너를 다시 띄워야 합니다.

### 3) 포트 개념이 헷갈림

예:

```bash
-p 9999:8080
```

뜻:

```text
내 컴퓨터 9999 → 컨테이너 8080
```

즉 왼쪽은 바깥, 오른쪽은 컨테이너 안쪽이라고 생각하면 쉽습니다.

### 4) 안 되는데 로그를 안 봄

문제가 생기면 거의 먼저 로그를 봐야 합니다.

## 13. IP란 무엇인가

IP는 쉽게 말하면:

> **컴퓨터의 주소**

입니다.

우리가 집 주소를 알아야 찾아갈 수 있듯이,
컴퓨터도 주소가 있어야 찾아갈 수 있습니다.

예를 들면 아래 같은 형태입니다.

```text
123.45.67.89
192.168.0.10
127.0.0.1
```

## 14. 공인 IP / 사설 IP / localhost 차이

---

### 14.1 공인 IP

공인 IP는:

> **인터넷 바깥에서도 보이는 주소**

입니다.

쉽게 말하면:

* 외부 사람이 찾아올 수 있는 주소
* 건물의 도로명 주소 같은 것

예:

```text
123.45.67.89
54.12.34.56
```

보통 외부에서 서버에 접속하려면 공인 IP나 도메인을 사용합니다.

---

### 14.2 사설 IP

사설 IP는:

> **집이나 회사 내부 네트워크에서만 쓰는 주소**

입니다.

쉽게 말하면:

* 내부 사람들끼리만 쓰는 주소
* 건물 안의 방 번호 같은 것

대표적인 형태:

```text
192.168.x.x
10.x.x.x
172.16.x.x ~ 172.31.x.x
```

예:

```text
192.168.0.20
10.0.0.5
```

---

### 14.3 localhost

`localhost`는:

> **내가 지금 쓰고 있는 그 컴퓨터 자기 자신**

입니다.

보통 아래와 같습니다.

```text
127.0.0.1
```

즉:

* `localhost`
* `127.0.0.1`

은 거의 같은 뜻입니다.

쉽게 말하면:

> “나 자신”

---

## 15. 공인 IP는 누가 주는가

공인 IP는 보통 **인터넷 제공자나 클라우드 제공자**가 줍니다.

### 집이나 회사 인터넷의 경우

보통 통신사나 인터넷 회사가 줍니다.

예:

* KT
* SK브로드밴드
* LG U+

### 클라우드 서버의 경우

클라우드 회사가 줍니다.

예:

* Oracle Cloud
* AWS
* Azure
* GCP

즉:

> **공인 IP는 내가 아무 숫자나 정하는 것이 아니라, 주소를 관리하는 쪽이 할당해주는 것**

입니다.

---

## 16. 네트워크란 무엇인가

네트워크는 쉽게 말하면:

> **컴퓨터끼리 연결되는 길**

입니다.

서버가 혼자 있으면 아무 일도 할 수 없습니다.

* 사용자도 접속해야 하고
* 다른 서버와도 통신해야 하고
* 데이터베이스와도 연결되어야 합니다

이 연결을 가능하게 해주는 것이 네트워크입니다.

비유하면:

* 서버 = 사무실
* 네트워크 = 도로 / 복도

---

## 17. 가상 네트워크란 무엇인가

가상 네트워크는:

> **클라우드 안에서 내가 만든 네트워크 공간**

입니다.

클라우드에서는 서버가 아무 데나 떠 있는 것이 아니라,
어떤 네트워크 안에 속해 있어야 합니다.

쉽게 말하면:

* OCI에서는 `VCN`
* AWS에서는 `VPC`

라고 부릅니다.

비유하면:

> **가상 네트워크 = 내가 빌린 건물 단지 전체**

그 안에 서버도 두고, 규칙도 정하고, 구역도 나눕니다.

---

## 18. 서브넷이란 무엇인가

서브넷은:

> **가상 네트워크 안의 더 작은 구역**

입니다.

비유하면:

* 가상 네트워크 = 아파트 단지 전체
* 서브넷 = 단지 안의 동별 구역

쉽게 말하면 네트워크를 더 잘게 나눠서 관리하는 개념입니다.

보통 아래처럼 생각할 수 있습니다.

### 공용 서브넷

외부 인터넷과 연결될 수 있는 구역

### 사설 서브넷

외부에서 바로 못 들어오는 내부 구역

---

## 19. 포트란 무엇인가

포트는:

> **서버 안의 출입문 번호**

라고 생각하면 쉽습니다.

컴퓨터 주소(IP)만 있다고 바로 모든 프로그램에 접속할 수 있는 것은 아닙니다.
같은 컴퓨터 안에도 여러 프로그램이 있을 수 있기 때문입니다.

예를 들면:

* `22` = 원격 접속용 문
* `80` = 웹 접속용 문
* `443` = 보안 웹 접속용 문
* `8080` = 개발용 웹 프로그램 문

즉:

* IP = 건물 주소
* 포트 = 몇 번 출입문인지

---

## 20. SSH는 무엇인가

SSH는:

> **원격으로 다른 컴퓨터에 접속하는 방법**

입니다.

쉽게 말하면
내 컴퓨터에서 다른 서버 안으로 들어가는 방법입니다.

예를 들어 서버에 접속할 때 보통 아래처럼 씁니다.

```bash
ssh 사용자명@IP주소
```

---

## 21. `ssh 사용자명@IP주소`의 뜻

예:

```bash
ssh ubuntu@123.45.67.89
```

뜻은 아래와 같습니다.

* `ssh` = 원격 접속하겠다
* `ubuntu` = 로그인할 사용자 이름
* `123.45.67.89` = 접속할 서버 주소

즉:

> “123.45.67.89 주소에 있는 서버에 ubuntu 계정으로 접속하겠다”

는 뜻입니다.

---

## 22. 로컬 / 서버 / 내부망 차이

이 부분도 자주 헷갈립니다.

### 로컬

지금 내가 직접 쓰고 있는 내 컴퓨터

### 서버

프로그램이 돌아가는 다른 컴퓨터

### 내부망

같은 집 / 회사 안에서만 통하는 네트워크

예를 들면:

* 내 컴퓨터에서 `localhost:8080`
  → 내 컴퓨터 자신

* `192.168.0.20`
  → 같은 회사나 집 네트워크 안의 다른 장비일 수 있음

* `123.45.67.89`
  → 인터넷에서 보이는 외부 주소일 수 있음

---

## 23. 서비스가 안 될 때 생각하는 순서

서비스가 안 된다고 해서 무조건 프로그램만 문제인 것은 아닙니다.
아래 순서로 생각하면 훨씬 쉽습니다.

### 1) 서버가 살아 있는가?

컴퓨터 자체가 켜져 있는가

### 2) 주소가 맞는가?

IP나 도메인이 맞는가

### 3) 네트워크는 연결되어 있는가?

길이 열려 있는가

### 4) 포트는 열려 있는가?

출입문이 열려 있는가

### 5) 프로그램이 실행 중인가?

Docker 컨테이너나 앱이 정상 동작 중인가

즉 문제는 아래 중 하나일 수 있습니다.

* 서버 문제
* 주소 문제
* 네트워크 문제
* 포트 문제
* 프로그램 문제

---

## 24. 꼭 기억해야 할 최소 핵심 정리

### Docker 관련

* **Docker** = 프로그램과 실행 환경을 함께 포장하는 도구
* **Image** = 실행 원본
* **Container** = 실행 중인 상태
* **Dockerfile** = 포장 방법 설명서
* **Docker Compose** = 여러 컨테이너 묶음 관리 도구

### IP / 네트워크 관련

* **IP** = 컴퓨터 주소
* **공인 IP** = 외부 인터넷에서 보이는 주소
* **사설 IP** = 내부 네트워크용 주소
* **localhost** = 나 자신
* **네트워크** = 컴퓨터들이 연결되는 길
* **포트** = 서버 안의 출입문 번호
* **SSH** = 원격으로 다른 컴퓨터에 접속하는 방법

---

## 25. 결론

* 프로그램은 그냥 실행되는 것이 아니라 **어딘가의 컴퓨터(서버)** 에서 돌아간다.
* 그 서버는 **주소(IP)** 를 가지고 있다.
* 컴퓨터끼리는 **네트워크**를 통해 연결된다.
* Docker는 프로그램을 **실행하기 좋은 상태로 포장해서 쉽게 실행하게 해준다.**
* 문제가 생기면 프로그램만이 아니라 **서버, IP, 네트워크, 포트**도 함께 봐야 한다.
